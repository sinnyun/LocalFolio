# @folio/workspace-files-ui · 文件浏览器

文件浏览器工作区的**界面层**，形态 A：它把 `@folio/base-frame-ui` 的四区框架当作自己的 `MainView`，只注册一个应用并声明四个区域。布局、分隔条、折叠、宽度持久化、逐区 `Suspense` 与错误边界都归框架；磁盘相关的一切（列目录、驱动器容量、分类、系统缩略图、媒体流、收藏与标签落盘）全归 `@folio/workspace-files-host`（见 `plugins/workspace-files-host/docs/DETAIL.md`）。

```text
┌ Left ────────────┬ Main ──────────────────────────────┬ Right ───────────────┐
│ 收藏夹           │ 导航 · 面包屑 · 双栏开关           │ 预览 · 音视频 · 文本 │
│ 标签             │ 统一集合视图：筛选 · 类型 · 星级   │ 星级 · 标签 · 备注   │
│ 快捷文件夹       │ 分组 · 排序 · 网格/瀑布/等高/列表  │ 复制路径与定位       │
│ 驱动器容量条     │ 右键菜单 · 拖出 · 灯箱             │ 元数据与属性         │
│ 文件树（懒加载） │ 一栏或双栏（独立历史）             │ 折叠交给框架         │
├──────────────────┴────────────────────────────────────┴──────────────────────┤
│ Status：栏位 · 目录名 · 筛选计数 · 已选文件摘要                              │
└──────────────────────────────────────────────────────────────────────────────┘
```

左栏图标轨折叠（`Ctrl+B`）与右栏折叠（`Ctrl+Alt+R`）由框架提供，插件不实现、也不拦截这两个键。

## 它做什么

本地文件与 Windows 系统缩略图的浏览界面：左侧收藏 / 标签 / 快捷文件夹 / 驱动器 / 文件树，中间一栏或两栏目录视图，右侧单文件检查器，底部信息栏显示当前栏位置与计数。界面**不持有任何磁盘事实**——目录内容、驱动器容量、文件分类、缩略图、媒体流、收藏夹、标签、星级与备注全部由 Host 计算或持久化，这里只负责调用与渲染。

## 四区声明

`createFilesApp()` 返回的 `FrameAppDefinition`：

| 区域 | 组件（`src/components/`） | 职责 |
|---|---|---|
| 左 `Left` | `FilesSidebar` | 收藏夹分组、标签列表、快捷文件夹、驱动器容量条、懒加载文件树 |
| 中 `Main` | `FilesMain` | 一个或两个 `FilePane`、收藏夹/标签管理弹层、图片灯箱 |
| 右 `Right` | `FilesInspector` | 单文件预览、快捷操作、星级/标签/备注、元数据与定位 |
| 底 `Status` | `FilesStatus` | 当前栏位、目录名、计数与截断标记、已选文件摘要 |
| `Provider` | `FilesProvider`（`src/context.tsx`） | 四区共用的 `useFiles()` 上下文，一次挂载 |

其余字段要点：

```ts
id: 'files.browser', workspaceId: 'files', order: 1,
title: '文件浏览器', subtitle: '本地文件与缩略图',
rightTitle: '文件检查器', leftCollapse: 'icon',
defaultLayout: { leftWidth: 264, rightWidth: 320, leftCollapsed: false, rightCollapsed: false },
```

工作区贡献是 `id: 'files'`、`order: 2`、`MainView: ctx.folioFrame.WorkspaceHost`，所以框架的用户宽度设置会覆盖 `defaultLayout`，`rightTitle` 是右栏标题栏文案。

## 页面结构

`FilesMain` 只做三件事：铺 `FilePane`（双栏时中间一条 1px 分隔线）、挂两个管理弹层、挂灯箱。真实结构在 `FilePane` 的两段里：

| 段 | 内容 |
|---|---|
| 导航行 | 后退 / 前进 / 上一级 / 刷新；面包屑、标签聚合头或路径输入框；左栏是双栏开关，右栏是「关闭右栏」 |
| 统一集合视图 | `@folio/base-collection-ui` 的 `CollectionBrowser`：文件名筛选、类型筛选、星级筛选、隐藏文件开关、分组方式、排序依据 + 升降序、卡片尺寸滑杆、网格/瀑布/等高/列表四视图、折叠全部分组；主体是同一套虚拟化布局，卡片由本插件渲染 |

- **视图**：网格（等比缩略图格）、瀑布（按缩略图宽高比堆叠）、等高（同一行等高、按比例分宽）、列表（五列固定行 + 固定表头）。缩略图解码后把真实宽高比回报给共享缓存，瀑布/等高只重排一次。
- **分组**：不分组、按时间（今天 / 昨天 / 本周 / 本月 / 今年 / 更早）、按类型（文件夹 / 图片 / 视频 / 音频 / 文档 / 代码 / 压缩包 / 其他 的固定序）、按名称（`0-9` / `A`–`Z` / 中文与符号 / 其他）、按文件夹（当前目录文件一组 + 每个子目录一组，可直接「进入目录」）。分组桶与项目库共用 `base-collection-ui` 的 `grouping.ts`。点组标题可折叠，组标题右侧的数字带 `+` 表示该组被截断。
- **缩略图桶**：卡片尺寸默认 `176`，滑杆 `96–256`、步长 `16`；请求尺寸取 `round(cardSize × 1.25)` 吸附到 `96 / 160 / 256 / 512` 四档，且只对 `entry.thumbSupported` 为真的条目请求。
- **列表视图**：五列固定布局（名称 / 标记 / 类型 / 大小 / 修改时间），名称列带 `48px` 小缩略图，表头固定在滚动区上方。
- **排序**：按名称（自然序）、修改时间、大小、类型、星级；升降序独立切换。除「按类型分组」和按文件夹分组里的「当前目录文件」组外，文件夹始终排在文件前。

## 主要交互

快捷键挂在 `FilePane` 的 `<section tabIndex={-1}>` 上，**必须先点进该栏**。焦点落在 `input / textarea / select / [contenteditable]` 里时，只有 `Ctrl+L` 与 `Ctrl+F` 仍然生效，导航类按键交给输入框自己处理。

| 键 | 作用 |
|---|---|
| `Ctrl+L` | 面包屑换成路径输入框（`Enter` 提交、`Esc` 放弃并还原、失焦只是退出输入） |
| `Ctrl+F` | 聚焦该栏的文件名筛选框 |
| `Alt+←` / `Alt+→` | 后退 / 前进（每栏独立历史，标签聚合视图也进历史） |
| `Alt+↑` | 上一级；在标签聚合视图里退回最近一个目录 |
| `Backspace` | 等价于「上一级」 |
| `Ctrl+Enter` | 保存检查器备注（失焦同样会保存） |

- **双击条目**：目录进入、图片打开灯箱、其它文件忽略（界面没有打开外部程序的入口）。
- **右键条目**：交给 `folioInteractions` 渲染桥接菜单，菜单内容由插件按条目动态解析：

| 菜单项 | 出现条件 | 行为 |
|---|---|---|
| 进入文件夹 | 目录 | 当前栏进入 |
| 查看大图 | 图片 | 打开灯箱，图集 = 该栏所有图片（含父子分组里的），按当前顺序 |
| 在另一栏中打开 | 总是 | 切双栏，把该目录（文件取其父目录）载入另一栏 |
| 收藏文件夹 / 取消收藏文件夹 | 目录 | `files.favorites.add` / `files.favorites.remove` |
| 星级评分 ▸ 清除 / 1–5 星 | 总是 | `files.meta.set` |
| 标签 ▸ 逐个打勾切换 / 管理标签… | 总是 | `files.meta.set`（切换成员）或打开标签管理器 |
| 复制图片 / 下载原文件 / 另存为… | 非目录（`复制图片` 仅图片，`另存为` 还要 `canSaveAs()`） | 交给 `folioInteractions`，失败由菜单统一提示 |
| 复制完整路径 / 在系统资源管理器中打开 | 总是 | 剪贴板（失败回退隐藏 `textarea`）／`files.reveal` |

- **拖出**：非目录条目在 `pointerdown` 预建拖拽会话（`url` = `/lf/files/download?…`、`paths` = 原路径、`sourceWorkspace: 'files'`），桌面端原生拖拽接管时取消浏览器拖拽；拖拽结束释放会话。
- **灯箱**：放大 / 缩小 / 上一张 / 下一张 / 关闭 全部由 `@folio/base-ui-kit` 的 `Lightbox` 提供，插件只把当前栏图片池与起始下标传进去。
- **双栏**：只有两栏，没有同步滚动；活动栏用内描边高亮，`FilesStatus` 显示「左栏 / 右栏」标记。
- **文件树**：点箭头懒加载一层（`files.tree`），点名字在当前活动栏导航；「在文件树中定位当前目录」用面包屑祖先链批量展开，只在当前栏是普通目录时可用。
- **快捷文件夹与固定**：`+` 把当前目录固定为快捷文件夹（`files.prefs.pin`），已固定项悬停出现取消固定。文件夹在当前目录上的「星」是**收藏夹**，与快捷文件夹是两套数据。
- **两个管理弹层**：收藏夹管理器（分组新建/改名/配色/上下移、条目改名/换组/上下移/打开/移除、按名称与路径搜索、把当前目录以别名加入指定分组）；标签管理器（新建带颜色与描述、搜索、改名改色、删除、点标签跳到聚合视图）。

## 数据与状态

调用的 Host 动作（为什么调用，不复述 Host 的路由表）：

| 动作 | 界面侧用途 |
|---|---|
| `files.roots` | 首屏与固定/取消固定后的快捷文件夹、驱动器与容量 |
| `files.list` | 每栏导航；`includeSubdirChildren` 只在分组切到「父子文件夹」时为真 |
| `files.tree` | 文件树展开一层；`showHidden` 取**左栏**的设置 |
| `files.inspect` | 检查器选中项的详情（预览 URL、文本片段、图片尺寸、子项计数） |
| `files.favorites.*` | 侧栏收藏、目录星标、收藏夹管理器的全部写操作 |
| `files.meta.get` / `set` / `pruneMissing` | 星级、标签、备注；标签聚合视图的失效记录清理 |
| `files.tags.*` / `files.tags.files` | 标签管理器的增删改、聚合视图取文件与 `missingPaths` |
| `files.prefs.pin` / `unpin` | 快捷文件夹 |
| `files.reveal` | 检查器与右键菜单的「在资源管理器中打开」 |

媒体与缩略图走三条只读路由（都带 `v=<mtime 取整>` 做缓存失效）：`/lf/files/thumb?size=<桶>`、`/lf/files/media`、`/lf/files/download`。

持久化只有一个键 `localStorage['folio.files.ui.v1']`：

```ts
{ dualPane, viewMode, cardSize, groupBy, sortBy, sortDir, showHidden, leftPath, rightPath }
```

- `viewMode` 为 `grid | waterfall | equal | list`；`groupBy` 为 `none | time | type | name | folder`。旧版本写入的 `gridSize` 会迁移为 `cardSize`，旧 `parent` 分组会迁移为 `folder`。
- 视图偏好取**当前聚焦栏**的值写回（两栏共用一份），左右路径各自保存；刷新后按 `leftPath` / `rightPath` 恢复，`dualPane` 为真时右栏同时载入。
- **不持久化**：`filterQuery`、`categoryFilter`、`minRating`、导航历史与游标、选中项、文件树展开状态、灯箱状态。刷新即回到默认筛选与空选中。

组件内状态：`panes`（每栏的目录、条目、历史、视图偏好、加载/错误）、`activePaneId` 与 `selectedEntry`（选中项跨栏共享）、`treeChildren` / `treeExpanded` / `treeLoading`、`lightbox`、两个弹层的开关。导航用每栏一个 `AbortController` 取消上一请求；标签/星级/备注写库是「先本地乐观更新，成功后用 Host 返回的 `tagCounts` 校正，失败再 `files.meta.get` 回灌」。

## 与 Host 的分工

- 界面负责：四区内容、两栏与全部视图状态、面包屑/路径输入、筛选/分组/排序/四视图、检查器、右键菜单内容解析、拖拽会话、灯箱、两个管理弹层。
- Host 负责：列目录与截断、驱动器容量、分类与 MIME、Windows 系统缩略图、媒体流/下载、收藏与标签与元数据持久化、资源管理器定位。**缩略图生成与缓存都在 Windows Shell 里**，界面不缓存也不生成。
- 单目录上限、`childGroups` 的 40×100 截断、缩略图 204 语义等细节见 Host 文档；界面侧只要记住「条目可能被截断」并显示 `已截断`。

## 限制与边界

- **没有多选**：检查器一次只渲染一个选中项，也没有批量打标签、批量导出。
- **从不写用户文件**：没有新建、重命名、删除、移动、剪切；`files.*` 的写操作只落在 Host 的 JSON 存储里。
- **没有路径白名单**：`Ctrl+L` 手输的路径原样交给 `files.list`，相对路径会相对 Host 进程的工作目录解析；能不能读由 Host 侧进程权限决定。
- 大目录是「截断 + 提示」，不是分页；只能靠筛选或退出该目录。
- 面包屑超过 5 段时折叠成「首段 + … + 末 4 段」，中间层只能靠 `Ctrl+L` 手输。
- 缩略图仅 Windows 可用：Host 返回 `204` 或加载失败时回退到类型图标 + 扩展名徽标；界面不请求 `fallback=icon`，音频、代码、压缩包即使系统有图标也不会拿到缩略图。
- 剪贴板写失败（无 `navigator.clipboard` 且 `execCommand` 不可用）只弹提示，没有别的回退。
- 标签聚合视图里的失效记录只能整体清理（`files.meta.pruneMissing`），没有逐条重选路径的能力。
- 文件树与活动栏的隐藏文件开关不一致：树的 `showHidden` 永远取左栏，两栏设置不同时树跟随左栏。
- 文件编辑与其它扩展能力将作为独立的 `feature-*` 功能插件挂载到本工作区，不塞进这个界面插件。
